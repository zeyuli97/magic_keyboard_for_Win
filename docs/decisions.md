# Implementation decisions

2026-10-22, initial development preview. Source: [execution specification](https://docs.google.com/document/d/1GlBcn8PpgCiUHCXzl3kUaBjWpS909ThDqEknYTjjow4).

1. **Single AHK process.** No Kanata, driver, elevation or startup integration. This does not prove recovery on Windows; tests remain NOT TESTED.
2. **Generated data instead of executable constants.** UTF-16LE INI (the encoding supported by Windows IniRead), SHA256 sidecar and manifest avoid executing generated code. Missing or corrupt data leaves the tray in Native Mode. Hashes detect corruption, not a malicious local editor who can replace both files. Only allowlisted actions/chords can load.
3. **Portable build without dependencies.** `.yaml` files use the JSON subset of YAML 1.2. Python 3.9+ stdlib validates and compiles them; packaged Windows runtime needs only AHK, not Python.
4. **IME fail-closed policy.** Only foreground HKL 04090409 is mapped. Selecting Chinese IME or an unknown layout bypasses the entire window. Full Chinese-IME mapping is not implemented; native input safety still requires real tests.
5. **Context handling.** Process allowlist and non-elevated token check; unknown errors bypass. Explorer restricted to folder window classes. VS Code requires explicit per-run acknowledgment of a manually installed bridge. Dedicated chords use VS Code's built-in `noop` as the fallback, because an empty command does not reliably consume a key. No native Ctrl shortcuts are overwritten.
6. **Known blockers stay disabled.** Windows Terminal copy/no-selection contract cannot be proven using this backend, so its entire host bypasses. Cmd+L and recycle-bin-only Explorer deletion are not registered. Native LWin+L can still lock Windows.
7. **No hardware attribution.** Left Win vs physical Ctrl are distinguished, but multiple keyboards are not. Mapping applies to all keyboards while enabled. This does not satisfy device-specific isolation.
8. **Input state.** Complete bounded sends minimize held outputs; only app switching owns synthetic LAlt. Hotkey predicates use physical modifier state, snapshot rule/foreground, and recheck before sending. Focus races consume instead of replaying into another app. These mitigations are not atomic OS delivery guarantees; adversarial focus/hold testing remains required.
9. **Review follow-up scope.** Fix action/profile capability validation, Native registration checks, missing-module test failures and Git-indexed reproducible packaging before asking for hardware acceptance. Windows CI uses a pinned hash-verified AHK under a verified restricted token; the production administrator rejection is unchanged. T03 stays required and BLOCKED, with no release-scope waiver. IME expansion, unmatched-chord swallowing, copyOnSelect, drivers, Explorer deletion and input timing remain separate decisions/experiments. See review-followup.md.
10. **Alt output guard (2026-10-23 candidate, not hardware-verified).** An Option chord leaves Alt logically down, and AHK must release and restore it around the output. Two things may misread that: WinUI access keys may ignore Ctrl (AHK's default mask key) as an intervening key, and the default Left Alt+Shift input-language hotkey sees a lone Alt+Shift because the hook suppressed the real key. The guard sends an unassigned `vkE8` before and after such output, and the mask key becomes `vkE8`. Physical Alt is still never released blindly, and no layout, scope or passthrough rule changes. If hardware shows the guard insufficient, the remaining options are a contract change (hide Option from apps as a prefix key) or closing Option mappings in WinUI apps. (User retest, 2026-10-23: mappings including Option navigation work under ENG with this build. This is a user report, not a hardware PASS.)
11. **Microsoft Pinyin English mode (stage 1 candidate, superseded by 12 the same day).** Pinyin mapped like US only while the focus window's IME conversion mode lacked the native bit; Chinese mode bypassed. Removed before integration.
12. **Simplified Chinese IME maps in both modes (2026-10-23 candidate, user-approved, not hardware-verified).** This refines decision 4. HKL 08040804 maps like US whether Pinyin is in Chinese or English mode, and no IME state is read. Mappings need left Command or Option held, which pinyin typing never uses, so only a chord pressed during composition is at stake. It sends the same Windows shortcut that pressing it natively would: the pending pinyin may be committed as letters or dropped, and the shortcut runs. Bypassing instead turned Mac habits into Windows shortcuts (Win+A Quick Settings, Win+Left window snap, Alt+Left Back in Chrome), which disrupt more. Composition detection was rejected: it helps only if chords are swallowed during composition, and costs a cross-process UI Automation query per chord plus per-application support checks. Rollback: remove 08040804 from `apps.allowed_hkls` and regenerate.
