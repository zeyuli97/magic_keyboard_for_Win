# Implementation decisions

2026-10-22, initial development preview. Source: [execution specification](https://docs.google.com/document/d/1GlBcn8PpgCiUHCXzl3kUaBjWpS909ThDqEknYTjjow4).

1. **Single AHK process.** No Kanata, driver, elevation or startup integration. This does not prove recovery on Windows; tests remain NOT TESTED.
2. **Generated data instead of executable constants.** UTF-16LE INI (the encoding supported by Windows IniRead), SHA256 sidecar and manifest avoid executing generated code. Missing or corrupt data leaves the tray in Native Mode. Hashes detect corruption, not a malicious local editor who can replace both files. Only allowlisted actions/chords can load.
3. **Portable build without dependencies.** `.yaml` files use the JSON subset of YAML 1.2. Python 3.9+ stdlib validates and compiles them; packaged Windows runtime needs only AHK, not Python.
4. **IME fail-closed policy.** Only foreground HKL 04090409 is mapped. Selecting Chinese IME or an unknown layout bypasses the entire window. Full Chinese-IME mapping is not implemented; native input safety still requires real tests. (Refined by decisions 11 and 12.)
5. **Context handling.** Process allowlist and non-elevated token check; unknown errors bypass. Explorer restricted to folder window classes. VS Code requires explicit per-run acknowledgment of a manually installed bridge. Dedicated chords use VS Code's built-in `noop` as the fallback, because an empty command does not reliably consume a key. No native Ctrl shortcuts are overwritten.
6. **Known blockers stay disabled.** Windows Terminal copy/no-selection contract cannot be proven using this backend, so its entire host bypasses. Cmd+L and recycle-bin-only Explorer deletion are not registered. Native LWin+L can still lock Windows.
7. **No hardware attribution.** Left Win vs physical Ctrl are distinguished, but multiple keyboards are not. Mapping applies to all keyboards while enabled. This does not satisfy device-specific isolation.
8. **Input state.** Complete bounded sends minimize held outputs; only app switching owns synthetic LAlt. Hotkey predicates use physical modifier state, snapshot rule/foreground, and recheck before sending. Focus races consume instead of replaying into another app. These mitigations are not atomic OS delivery guarantees; adversarial focus/hold testing remains required.
9. **Review follow-up scope.** Fix action/profile capability validation, Native registration checks, missing-module test failures and Git-indexed reproducible packaging before asking for hardware acceptance. Windows CI uses a pinned hash-verified AHK under a verified restricted token; the production administrator rejection is unchanged. T03 stays required and BLOCKED, with no release-scope waiver. IME expansion, unmatched-chord swallowing, copyOnSelect, drivers, Explorer deletion and input timing remain separate decisions/experiments. See review-followup.md.
10. **Alt output guard (2026-10-23 candidate, not hardware-verified).** An Option chord leaves Alt logically down, and AHK must release and restore it around the output. Two things may misread that: WinUI access keys may ignore Ctrl (AHK's default mask key) as an intervening key, and the default Left Alt+Shift input-language hotkey sees a lone Alt+Shift because the hook suppressed the real key. The guard sends an unassigned `vkE8` before and after such output, and the mask key becomes `vkE8`. Physical Alt is still never released blindly, and no layout, scope or passthrough rule changes. If hardware shows the guard insufficient, the remaining options are a contract change (hide Option from apps as a prefix key) or closing Option mappings in WinUI apps. (User retest, 2026-10-23: mappings including Option navigation work under ENG with this build. This is a user report, not a hardware PASS.) The same trailing guard now also follows outputs that drop a held Shift, such as Command+Shift+Z sending Ctrl+Y, against a possible lone-Shift reading by the IME; also not hardware-verified.
11. **Microsoft Pinyin English mode (stage 1 candidate, superseded by 12 the same day).** Pinyin mapped like US only while the focus window's IME conversion mode lacked the native bit; Chinese mode bypassed. Removed before integration.
12. **Simplified Chinese IME maps in both modes (2026-10-23 candidate, user-approved, not hardware-verified).** This refines decision 4. HKL 08040804 maps like US whether Pinyin is in Chinese or English mode, and no IME state is read. Mappings need left Command or Option held, which pinyin typing never uses, so only a chord pressed during composition is at stake. It sends the same Windows shortcut that pressing it natively would: the pending pinyin may be committed as letters or dropped, and the shortcut runs. Bypassing instead turned Mac habits into Windows shortcuts (Win+A Quick Settings, Win+Left window snap, Alt+Left Back in Chrome), which disrupt more. Composition detection was rejected: it helps only if chords are swallowed during composition, and costs a cross-process UI Automation query per chord plus per-application support checks. This departs from the specification's P0 Chinese IME rule (bypass when composition cannot be handled or identified) and needs Lead sign-off; T06 cannot PASS on composition behaviour until then. The layout is read from the focus window's input thread, not the top-level window's (contract amendment). Rollback: remove 08040804 from `apps.allowed_hkls`, regenerate and restart MacFlow.
13. **Opt-in start at sign-in (2026-10-23, user-requested, not hardware-verified).** This refines decision 1 and follows the specification: start at sign-in only after the user chooses it, first start Native, uninstall removes it. A tray check item writes or removes one per-user Startup shortcut that records the running copy's AutoHotkey and script paths. A Startup shortcut was chosen over a registry Run key or a scheduled task: no registry writes, visible in Explorer and in Windows' startup-apps list (which only disables it), removable from the tray or Explorer, never elevated. Its paths are absolute, so a moved folder is fixed by choosing the item once from the new copy; the item asks before replacing a shortcut that starts another copy.
14. **Four more applications mapped like Notepad (2026-10-23, user-requested, not hardware-verified).** Claude desktop (claude.exe), Codex desktop (ChatGPT.exe), Visual Studio (devenv.exe) and Unreal Editor 5 (UnrealEditor.exe) take Notepad's edit and text mappings; VS Code stays on its bridge. No bridge like VS Code's was built: Claude and Codex offer no user keybindings, and bridges for Visual Studio's and Unreal's scoped shortcuts would each need their own setup, collision checks and tests. So their built-in terminal panels get the editor outputs (Command+C with nothing selected interrupts; Command+Z and Command+S affect bash), and Unreal's viewport reads Home/End as its own commands (End snaps the selection to the floor). The user accepted this to have the mappings in the applications they use daily. Browser chords stay off in these applications, since an application menu may bind Ctrl+R or Ctrl+W to reload or close the window. Departs from the specification's terminal rule for terminal panels; needs Lead sign-off. Rollback: disable the profile in `config/apps.yaml`, regenerate and restart.
15. **Option+Up/Down move by paragraph (2026-10-24, user-requested, not hardware-verified).** Unmapped, Option+Up/Down reached Notepad as native Alt+Up/Down: no caret movement, and Option+Up hid the caret until a click (user report). They now send Ctrl+Up/Down, with Shift for selection, which move by paragraph in RichEdit (Notepad's editor) and Chromium text; macOS moves to the start/end of the paragraph. A separate `paragraph` context limits this to Chrome, Notepad, Claude and Codex. VS Code and Visual Studio keep native Alt+Up/Down, which moves the line as Option+Up/Down does in VS Code on macOS; there Ctrl+Up/Down would only scroll. Explorer keeps Alt+Up for the parent folder, and Unreal Editor's text boxes are unverified. Extends the specification's P0 TEXT list; needs Lead sign-off. Rollback: disable the four rules, regenerate and restart.
