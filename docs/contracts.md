# Implementation contract v1

Status: frozen for the initial development preview, 2026-10-22. This is an implementation interface, not hardware evidence.

## Backend and scope

AHK v2.0.19+ (64-bit), single user-mode process. No Kanata at runtime. The script starts in Native Mode. Only a user tray action enables mappings. Exact left-side chords only; no physical Ctrl or right Win remap, no unconditional LWin-to-Ctrl conversion. No device attribution: applies to all keyboards when enabled, explicitly disclosed. `device_id=null`, `origin=unknown` (AHK hook lacks trustworthy device/injection metadata). Self-generated hotkeys are excluded with hook hotkeys `$` and input level 1, SendLevel 0.

Only the foreground thread's exact HKL `04090409` (US English) is initially allowed. Other layouts, including Chinese IME even in English mode, bypass the whole app. This deliberately avoids guessing composition state. Physical input remains native; IME safety is still NOT TESTED. Unknown integrity/process/layout => bypass. Elevated runtime is refused; elevated foreground windows bypass. (Amended 2026-10-23, see below: the focus window's input thread decides, and `08040804` is allowed.)

## Configuration v1

The three `.yaml` files use the JSON-compatible YAML 1.2 subset: standard JSON objects, no YAML-only syntax, comments, aliases or arbitrary tags. Python stdlib only. `tools/macflow_config.py` exposes `load_and_validate(root: pathlib.Path) -> dict` with keys `mappings`, `apps`, `release`; raises `ConfigError` (ValueError subclass). It also exposes `validate_bundle(bundle)` for tests. Root path is repository root.

- mappings: `{schema_version:1, mappings:[{id, enabled:bool, physical_chord, contexts:[str], action, priority:int, on_unmatched:"passthrough", blocked_reason:str}]}`. Blocked entries are disabled. Chord grammar: `LWin[+Shift]+key` or `LAlt[+Shift]+key`; key is a lower-case a-z, Left/Right/Up/Down/Backspace/Tab or bracket. No arbitrary AHK expressions. Unique IDs and unique chord/context at equal priority; reject overlaps across matched profile contexts as well.
- apps: `{schema_version:1, allowed_hkls:["04090409"] (amended 2026-10-23: a subset of 04090409 and 08040804), bypass_processes:[lowercase exe], profiles:[{id, processes:[lowercase exe], contexts:[str], enabled:bool, requires_integration:bool}]}`. Frozen ID/process pairs: chrome/chrome.exe, notepad/notepad.exe, vscode/code.exe, explorer/explorer.exe, windows_terminal/windowsterminal.exe (amended 2026-10-23: also claude/claude.exe, codex/chatgpt.exe, visual_studio/devenv.exe and unreal/unrealeditor.exe, each edit/text; see the app scope amendment). No ID may impersonate a terminal under an editor policy. Context subsets: Chrome edit/text/browser; Notepad edit/text (amended 2026-10-24: Chrome, Notepad, Claude and Codex also paragraph; see the paragraph navigation amendment); VS Code vscode; Explorer explorer; Windows Terminal terminal. Windows Terminal disabled; only VS Code requires a per-run confirmation of its manual bindings. Other profiles cannot request that integration.
- release: `{schema_version:1, delivery_status:"DEVELOPMENT PREVIEW", mode:"ahk-only", baseline:[str], cases:[{id, priority:"P0"|"P1"|"CONDITIONAL", required_prototype:bool, required_v1:bool, status:"NOT TESTED"|"BLOCKED"|"PASS"|"FAIL", reason:str}]}`. Cases correspond to spec T01..T09 subcases. Do not mark hardware PASS.

Allowed actions: copy,paste,cut,select_all,undo,redo,save,find,word_left,word_right,select_word_left,select_word_right,delete_word,line_start,line_end,document_start,document_end,app_next,app_previous,browser_address,browser_new,browser_close,browser_reload,browser_restore,browser_back,browser_forward,explorer_new,explorer_delete,terminal_copy,terminal_paste (amended 2026-10-24: also paragraph_up,paragraph_down,select_paragraph_up,select_paragraph_down).

Generator writes deterministic `build/generated/macflow.ini`, its `.sha256` sidecar and `manifest.json`. INI is UTF-16LE with BOM for Windows IniRead. Runtime verifies artifact and source-file hashes, then loads typed data, not executable generated AHK, so missing/malformed/stale data can remain Native instead of failing at #Include parse time. This refines the spec's “generated AHK constants” into a safer data format. No hand edits. SHA256 hashes detect corruption; they are not a security signature. `--check` detects stale artifacts without writing.

## AHK shared interfaces

Global `MF := {Enabled:false, Config:0, ConfigError:"", Root:root, VscodeReady:false, OwnedKeys:Map(), SwitcherActive:false, SwitchingHwnd:0, Registered:[]}`. Main sets it before calling initialization. Config/parse errors leave ConfigError visible and Enabled=false. All source includes are static project code.

- `MF_LoadConfig(root)` returns `{SchemaVersion, Hash, Rules:[], Profiles:[], BypassProcesses:[], AllowedLayouts:[]}`. Rule properties `Id,Enabled,Chord,Contexts,Action,Priority,BlockedReason`; profile `Id,Processes,Contexts,Enabled,RequiresIntegration`. Invalid artifact throws Error.
- `MF_RegisterMappings()` installs dynamic hook hotkeys using `HotIf(callback)` with per-chord selection; default context predicate is false when disabled. `MF_ResetInput()` releases only owned synthetic keys and clears switcher state; `MF_PollInput()` handles switcher LWin release/Esc/timeout and layout/focus safety. Never log actual key contents.
- `MF_CurrentProfile()` returns profile object or 0 after enabled/process/integrity/layout checks. Native VS Code dispatch is allowed only with `MF.VscodeReady=true` and profile integration requirement.
- `MF_SelectRule(chord, profile)` returns highest-priority enabled matching rule or 0; config rejects ambiguous matches. Priority: Native/bypass -> app context -> generic allowed profile -> native passthrough.
- `MF_RunAction(action, profile)` dispatches into profiles. Handlers `MF_GlobalAction(action, profile)`, `MF_BrowserAction(action, profile)`, `MF_ExplorerAction(action, profile)`, `MF_TerminalAction(action, profile)` return true if handled, false if unknown. No blind terminal generic fallback.
- `MF_SendTap(keys)` sends a complete bounded chord (SendEvent, SendLevel 0), no held outputs. `MF_HoldSynthetic(key)`/`MF_ReleaseSynthetic(key)` manage MF.OwnedKeys. `MF_CancelSwitch()` releases owned Alt and clears switcher. Only `LAlt` may be held across app-switch repetitions. `MF_GlobalAction` owns switcher action, using these helpers.
- `MF_SetEnabled(enabled, *)`, `MF_Disable(*)`, `MF_Quit(*)`, `MF_UpdateTray()` are lifecycle functions. Disable stops routing immediately; if a send is active, owned-key cleanup completes in its finally block. Timers/exit call shared reset. Whole-process crash recovery is a hardware test, not claimed verified.

## VS Code bridge and terminal limits

Native VS Code keybindings are manual opt-in, backed up by the user before merging. No runtime config writes. Use reserved Ctrl+Alt+F13..F24 and shifted variants; exact trigger/action mapping belongs in integrations/vscode/README.md and matches MF_GlobalAction's vscode branch. Include a lowest-priority built-in `noop` binding for every dedicated trigger, then higher-priority editor/terminal bindings with `when`. Empty commands do not reliably consume events; add noop and terminal copy/paste to commandsToSkipShell. No selection copy in terminal must consume/no-op. Never bind native Ctrl+C/D/Z or Win+L. `terminal.integrated.sendKeybindingsToShell=false` is a prerequisite. Installed fragments must not alter ordinary native inputs while MacFlow is disabled; collision check and original settings restoration are manual documented steps. VS Code integration remains NOT TESTED and disabled by default per run until user confirms setup.

Windows Terminal copy is BLOCKED because selection/no-op behavior is not reliably available through this backend. Entire host bypasses. Explorer deletion and Command+L are BLOCKED and never registered. Physical LWin+L may still lock Windows; Ctrl+L is the documented fallback. Other registered mappings are IMPLEMENTED / NOT TESTED, not compatibility claims.

## Lifecycle boundaries

Native Mode clears Enabled and releases only owned synthetic keys. Do not blindly release physical modifiers. On orderly exit/suspend/session change reset. App switching captures state at down and ends on LWin release, Esc, foreign physical modifiers, timeout or explicit disable. Pass-through transition hooks and polling clean up synthetic Alt; this still requires the held-key hardware tests. A bounded Critical dispatch transaction buffers ordinary hotkeys/timers. Low-numbered session/power messages can still interrupt it, so reset defers ownership cleanup until the active dispatch's finally block; OnExit forces cleanup because interrupted code will not resume. Final Enabled/foreground checks precede output. UI Enable refuses while modifiers are physically held. Emergency Ctrl+Alt+F12 disables only; mouse tray remains primary. No autorun (amended 2026-10-23: an opt-in start-at-sign-in shortcut only, see below), elevation, driver, clipboard reads/writes, or network.

## Verification

Static tests verify config semantics, deterministic generation, invalid configuration fail-closed policy and release gate logic. They inspect a restricted subset of AHK policy literals, not the complete AHK language, and do not execute AHK. Windows smoke runs `/validate`, then optionally configuration-only `--self-test` or Native-only `--registration-test`, when supplied an installed runtime. Genuine keyboard test statuses remain NOT TESTED even after syntax/smoke pass.

## Engineering review amendment (2026-10-22)

This amendment tightens validation and development checks; mapping scope, US-only layout policy, passthrough behavior, blocked features and release gates are unchanged.

- Validate every enabled rule against every matching declared profile's implemented actions, including profiles currently disabled. Chrome supports the 17 generic editor/text actions, app_next/app_previous and six implemented browser actions; Notepad and VS Code support the 17 generic actions and app switching; Explorer supports copy/paste/cut/select_all, explorer_new and app switching; Windows Terminal supports no enabled action. Reject a mismatch before generation and again in the AHK loader. Python exposes PROFILE_ACTIONS; AHK exposes MF_ProfileActionPolicy(). Tests compare policy tables and handler coverage without claiming to execute AHK.
- AHK policy accessors MF_ConfigActions(), MF_ConfigContexts(), MF_ConfigBlockedActions(), MF_ConfigProtectedChords(), MF_ConfigAllowedLayouts(), MF_ConfigProfilePolicy() hold the literal allowlists consumed by the loader. Static parity tests compare them with the corresponding Python constants and schema where applicable; missing source files fail the suite.
- Preserve --self-test as configuration-only/no-hook initialization. Add --registration-test to register the same HotIf/Hotkey/emergency paths as normal startup while Enabled=false and VscodeReady=false, then exit. It must never enable, dispatch or send an input action. No elevated AHK exception is permitted in CI. tools/smoke-tests.ps1 exposes -RegistrationTest and still runs /validate first. Registration success is neither a physical-input test nor a hardware PASS.
- tools/package-preview.py selects only Git-indexed regular files in its explicit release directories/top-level list, rejects unsafe paths/symlinks and fails when Git inventory is unavailable. It never falls back to a directory scan. Packaged bytes are the staged index blobs; a selected file whose working-tree bytes differ from its index blob is refused, so configuration checks and the archive see identical content. ZIP metadata, ordering and uncompressed storage are fixed for cross-platform reproducibility. --check rebuilds in memory, compares the committed dist/manifest.json, and writes nothing. tests/evidence/local and runtime/development caches remain excluded.
- CI runs portable checks plus a separate pinned, checksum-verified Windows AHK syntax/Native registration job. CI downloads belong to test setup only; installed MacFlow runtime remains offline. The restricted CI launcher removes the inherited PowerShell 7 PSModulePath via the environment provider before starting Windows PowerShell, which then builds its own default module path. The same CI-only helper is exercised under PowerShell 7.5+ for nonempty, empty and missing values; a Windows child process also checks core-module autoloading. A Windows CI result must be reported separately from Magic Keyboard/IME/application hardware evidence.

## Fix-round amendment (2026-10-23, pending Lead review and hardware retest)

Implemented on local branch `claude/alt-guard-fixes` after controlled Notepad tests showed Option+Left reaching the handler and send while the app showed F/E access keys and the caret did not move. Mapping scope, passthrough, blocked features, Native start and the physical Control/right Command boundary are unchanged. The only layout-policy change is the separate Simplified Chinese IME amendment below. None of the following is hardware-verified.

- `A_MenuMaskKey` is set to the unassigned `vkE8` before hooks are installed. The AHK 2.0.19 default is Ctrl (`vk11sc01D`), itself a modifier.
- `MF_SendTap(keys)` returns true only when the chord was sent. When physical LAlt is down (Option chords), it sends `{Blind}{vkE8}` before the output and again after it if Alt is logically down. Windows and apps then never see Alt, or Left Alt+Shift, pressed with only modifiers in between. This targets WinUI access keys, menu bars and the default input-language hotkey. The leading guard is a send of its own, so `MF_SendTap` then repeats the final checks in `MF_SendTargetSafe` (`MF_ForegroundSafe`, Enabled, same foreground window) and consumes the chord if any fails. The trailing guard goes only to the window that received the output (Codex review CR1). When physical Shift is held and the output has no Shift (Command+Shift+Z sends Ctrl+Y), the trailing guard is also sent while Shift is logically down, so an IME cannot read the restored Shift and the user's release as a lone Shift tap (hypothesis guard, NOT hardware-verified). Other LWin chords and the Alt-Tab path are not wrapped. The output target is the dispatch window when there is one, read once (review of 2026-10-23).
- `MF_ReleaseSynthetic(key, masked := false)` and `MF_CancelSwitch(masked := false)` add an optional masked release (`vkE8` before Alt up). The app-switch action uses it when its first Tab was not sent. In that case it releases the owned Alt immediately instead of holding it until Command release or the timeout. Masking is not used while the Alt-Tab switcher may be open.
- `MF_CurrentProfile(&reason := "")` and `MF_ForegroundSafe(hwnd, &reason := "")` optionally return a bypass label built from fixed templates; a label may name the process or the HKL, never keys, text, titles or clipboard data. The predicate and handler keep only the latest decision label and tick in RAM (`MF.LastDecision`) for the Status dialog. Key names, chords, text, titles and clipboard data are never recorded.
- `main.ahk` uses `#Warn All, StdOut`; `tools/smoke-tests.ps1` fails when AHK reports any warning.
- Release gates may take the coverage map in `tests/mapping-spec.yaml`: each case lists the rules and profiles it exercises. Every enabled rule in every enabled profile it reaches needs a required case (which must PASS anyway) or a PASS case. Mappings that rely only on deferred P1 cases block the prototype, and mappings that no case exercises block both gates. A missing or invalid map blocks both gates; configuration validity is unaffected.
- The preview archive also carries `.github/workflows/static-checks.yml`, so its own test suite runs from the extracted archive. Packaging tests select fixture files with the packager's path rule instead of requiring the source tree to be a Git checkout.

## Simplified Chinese IME amendment (2026-10-23, user-approved for the preview; pending Lead review and hardware retest)

This is the only layout-policy change in this round. It replaces "Chinese IME bypasses even in English mode": the Simplified Chinese layout `08040804` (Microsoft Pinyin on the test host) maps like US in Chinese and English mode alike. It supersedes the same day's stage 1 candidate, which mapped Pinyin only in English mode and bypassed Chinese mode.

- `apps.allowed_hkls` is a nonempty, duplicate-free subset of `04090409` and `08040804`. Python (`ALLOWED_HKLS`), the schema enum and `MF_ConfigAllowedLayouts()` hold the same two values. The release configuration lists both. Removing `08040804`, regenerating and restarting MacFlow restores whole-window bypass for Chinese input; configuration loads only at start. The stage 1 field `ime_english_mode_hkls` is gone and is rejected as an unknown field.
- `MF_ForegroundSafe` decides by the layout of the input thread only. That is the thread of the focus window from `GetGUIThreadInfo`, or the foreground thread when the query succeeds and reports no focus window. A failed query fails with "focus window unavailable" instead of falling back (Codex review CR2). A focus window whose thread cannot be resolved fails with "focus thread unavailable". The top-level thread is deliberately not consulted. In Windows 11 Notepad the editor runs on its own thread, and a layout switch can leave the frame thread stale: on 2026-10-23 the frame read 08040804 while the editor that received the keys read 04090409. This made the original top-level check bypass while the user typed English. That top-level check was the likely root cause of the "Enabled with English but nothing maps" reports.
- No IME state is read: no conversion mode, open status or composition query, and no cross-process IME call in the hotkey decision.
- Rationale: mappings fire only with left Command or left Option held, which pinyin typing, candidate selection and the Shift mode switch never use. A mapped chord pressed during composition sends the same Windows shortcut (Ctrl+V, Home, Ctrl+Backspace and so on) that pressing it natively would, and the IME and application already handle that case. The expected worst case is that the pending pinyin is committed as letters or dropped, plus the shortcut's own effect; undo recovers text edits. Bypassing Chinese mode instead turned the same habits into Windows shortcuts (Win+A Quick Settings, Win+Left window snap, Alt+Left Back in Chrome). Detecting composition was considered and rejected. UI Automation `TextEditPattern.GetActiveComposition` tracked composition in Notepad on 2026-10-23, but it helps only if chords are swallowed during composition, and costs a cross-process query per chord plus a support check per application. Passing chords through during composition would be worse than mapping them.
- Specification deviation: the specification's P0 Chinese IME rule requires bypassing mappings when composition cannot be handled reliably, and bypassing the application or mode when it cannot be identified. T06 tests that this bypass works and accepts pausing mappings during composition. Mapping during composition without detection departs from both. The user accepted the trade-off for the preview; the deviation needs Lead sign-off, and T06 cannot PASS on composition behaviour until it is signed off or the specification changes.
- Limits: `08040804` identifies the Simplified Chinese layout, not Microsoft Pinyin; other Chinese (PRC) IMEs that report it also map and are untested. Behaviour during composition, the IME's Shift mode switch around `Command+Shift+Z` (AHK releases and restores the held Shift around `Ctrl+Y`) and every application remain NOT TESTED; see T06.

## Start-at-sign-in amendment (2026-10-23, user-requested; pending Lead review and hardware retest)

The specification allows start at sign-in only after the user chooses it, with the first start in Native Mode (Agent D; T07 "no autostart by default"; T08 "no unauthorized autostart"; uninstall removes the chosen item). This narrows the blanket "No autorun" in Lifecycle boundaries to that rule. AGENTS.md is reworded to match.

- Off by default. Only the tray item "Start at Windows sign-in (Native Mode)" creates or removes the shortcut. `MF_Main`, both test modes and every other path never write it.
- The only artifact is `MacFlow.lnk` in the user's Startup folder (AHK `A_Startup`). Its target is `A_AhkPath`, its argument is the quoted `A_ScriptFullPath`, and it starts in the repository root. There is no registry Run key, scheduled task or service, and it is never elevated. A sign-in start runs the same startup path as a manual start: Native Mode, the single-instance guard, manual Enable. Whether startup completes cleanly that early (for example the session-notification registration) is NOT TESTED; see T07. Windows' startup-apps toggle only disables the shortcut, and the tray still shows it as on.
- `MF_StartupState()` returns "this" when the shortcut starts this copy. It returns "other" when the shortcut starts another copy or a missing path, or cannot be read, and "" when there is none. A failed read counts as "other" before any output variable is compared, because `FileGetShortcut` leaves them unset. The tray check mark shows "this" from a cached state, refreshed when the tray is built, when Status opens and after every toggle. If a click finds that the shortcut changed outside MacFlow, it only refreshes the check mark and says so; it never acts on the stale state. Otherwise, choosing the item removes "this", creates the shortcut when there is none, and asks before replacing "other". After the folder moves, starting the new copy and choosing the item points the shortcut there.
- Quit does not remove the shortcut. Turning the option off, or deleting the shortcut, is part of rollback and uninstall.

## App scope extension amendment (2026-10-23, user-requested; pending Lead review and hardware retest)

The specification's first acceptance baseline names Chrome, Notepad, VS Code, Windows Terminal + PowerShell and Explorer, and other applications need item-by-item verification (source specification line 29). At the user's request, four more applications are mapped exactly like Notepad.

- Profiles: claude/claude.exe (Claude desktop app), codex/chatgpt.exe (Codex desktop app, whose executable is ChatGPT.exe, so a ChatGPT desktop app would match too), visual_studio/devenv.exe (Visual Studio) and unreal/unrealeditor.exe (Unreal Editor 5; UE4's UE4Editor.exe is not included).
- Contexts are edit and text only, with Notepad's handler: plain Ctrl, Home/End and Ctrl+arrow outputs. The validators reject browser, terminal and vscode contexts for these profiles.
- The process name cannot tell surfaces inside these applications apart. Built-in terminal panels (Claude, Codex, Visual Studio) receive the editor outputs: Command+C with nothing selected sends Ctrl+C, which interrupts the running command; in bash, Command+Z suspends it and Command+S can stop output (XOFF). This departs from the specification's rule that terminals disable these conversions by default, which still holds for terminal hosts. In Unreal Editor's level viewport, Home/End and Ctrl+Home/End are viewport commands; End snaps the selection to the floor by default. These are recorded in T01/T02 as accepted limitations, not PASS criteria.
- Coverage: the profiles are added to T01, T02 and T07d, so both release gates require their hardware runs. Rollback: set the profile's `enabled` to false in `config/apps.yaml`, regenerate and restart MacFlow.

## Paragraph navigation amendment (2026-10-24, user-requested; pending Lead review and hardware retest)

The specification's P0 TEXT list has no Option+Up/Down. Unmapped, it reaches applications as native Alt+Up/Down; in Windows 11 Notepad that moved no caret, and Option+Up hid the caret until the user clicked again (user report). On macOS, Option+Up/Down move to the start/end of the paragraph, and Shift extends the selection.

- New context `paragraph`, for profiles where Ctrl+Up/Down move by paragraph: Chrome, Notepad (its editor is a RichEdit control, `RichEditD2DPT`), Claude and Codex (Chromium). The validators reject it for every other profile.
- New actions and rules, in that context only: `paragraph_up` (LAlt+Up → Ctrl+Up), `paragraph_down` (LAlt+Down → Ctrl+Down), `select_paragraph_up` (LAlt+Shift+Up → Ctrl+Shift+Up), `select_paragraph_down` (LAlt+Shift+Down → Ctrl+Shift+Down). They go through the same Alt guard as the other Option chords. The handler sends them only to a profile with the paragraph context.
- Not mapped: VS Code and Visual Studio keep native Alt+Up/Down (move line, as Option+Up/Down does in VS Code on macOS). Explorer keeps Alt+Up (parent folder). Unreal Editor's text boxes are unverified.
- Known difference: Option+Down on macOS stops at the end of the current paragraph; Ctrl+Down moves to the next paragraph.
- Coverage: the rules join T02. Chrome is not a T02 profile, so the gates report Chrome's paragraph rules as UNCOVERED alongside its other text rules (open Lead decision). Rollback: disable the four rules in `config/mappings.yaml`, regenerate and restart MacFlow.
